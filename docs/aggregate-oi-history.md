# Local aggregate OI recovery

The Overall Direction supporting OI panel compares the same active OKX crypto USDT perpetual contracts in USD notional. Eligibility uses the shared instrument directory: instCategory=1, state=live, instType=SWAP, ctType=linear and settleCcy=USDT. Stocks, commodities, unknown classifications, inactive contracts, inverse contracts and delivery futures are excluded. The UI labels this crypto-only scope and shows the number of excluded non-crypto instruments. Missing instrument metadata withholds the aggregate; it never falls back to the old mixed total. This is separate from the scanner's contract-count OI signal. Notional changes include price changes and do not identify new longs versus shorts.

The local collector now repairs missing 15-minute, one-hour and four-hour aggregate baselines using the public `GET /api/v5/rubik/stat/contracts/open-interest-history` endpoint (`period=5m`, `limit=100`). A batch requests at most six contracts, using the existing shared rate limiter, cache and provider cooldown. The original bucket timestamps are retained; a bucket is usable only after its five-minute end. Each aggregate point uses a single common availability timestamp.

The percentage comparison requires at least 50 contracts, 90% of the current contract count and 90% of current USD OI. The same matched set is summed at both ends. The UI shows contract coverage, USD coverage, source, actual comparison duration and times. The displayed total includes measured current crypto contracts. At least 90% of the eligible crypto directory must have fresh current OI; any remaining missing current readings are disclosed. Missing/newly listed contracts are not treated as zero; sparse, invalid or future data cannot complete the history.

Progress and successful contract histories survive restarts in the local database. Recovery runs independently of browser tabs. Initial recovery can take several minutes for hundreds of contracts, and upstream rate limits or missing exchange history can delay it. It does not require waiting four hours to collect a new baseline. No history is interpolated or invented. Recovery continues toward **100% coverage for all three windows**, even after a usable 90% comparison is available. Only full coverage backs off to five minutes. Failed contracts retain their last good history and retry with bounded exponential backoff; new contracts are attempted before retries. Existing five-minute local collection continues.

Before the crypto-only filter, the former 451/499 result was a premature stop at the minimum usable threshold, not proof that 48 contracts lacked API history. The coverage details now show all three windows, unattempted/error counts and per-contract pending reasons. Partial USD coverage never rounds up to 100%. Selection prefers the fullest usable baseline within the original time tolerance, then the nearest timestamp. Full locally collected baselines avoid redundant historical API downloads. Only changed historical aggregates are written; richer saved points and original local observations are protected.

Existing mixed-market historical observations are projected onto the current crypto contract set at both comparison endpoints. Timestamps and original observations are preserved, so previously recovered crypto history remains usable immediately. Only crypto contracts are scheduled for further OI recovery. Legacy browser snapshots without the crypto scope marker are withheld until manual Refresh; opening the page does not automatically refresh them.

Contract recovery caches expire after 12 hours and are eligible for the existing bounded cache maintenance. Aggregate observations retain the existing 24-hour horizon. Watchlists, preferences, saved analyses and API keys are untouched.

The display remains manual: background work does not push changes into the open screen. Click **Refresh** on Overall Direction to display the latest recovered OI. Switching sections or horizons does not fetch new OI.

Tests: `node --test --test-concurrency=1 tests/*.test.mjs`. Live coverage evidence is in `data/verification/oi-crypto-live.json` (crypto-only) and `data/verification/oi-coverage-live.json` (prior mixed-universe audit). This change is local only; it was not published to the hosted site.
